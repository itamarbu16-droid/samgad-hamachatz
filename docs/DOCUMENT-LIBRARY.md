# Unit roles, personal category, library and meeting/inspection summaries

The bottom navigation is Home, Tasks, Personal, Library, and Summaries. The Personal category contains only the creator's private tasks and recurring monthly rhythm. Role groups and assignments live under Tasks, alongside the existing shared task list. Legacy links using `view=rhythm` are mapped to Personal. Blocked-task controls, counts and the assigned-by-me filter have been removed from the UI; historical records remain persisted. Existing synthetic blocked tasks are migrated to in-progress rather than deleted.

The role directory initializes the requested slots idempotently: סמ״פ א׳, סמ״פ ב׳, סמ״פ ג׳, סמ״פ ד׳, סמ״פ צמ״ה, סמ״פ הוריקן, סמ״פים (קבוצה), סקשר״גית, ממחגית. Slots can have one or more eligible active-account emails. Empty slots cannot silently create a private task. Synthetic fixture account names are position labels; a guarded hosted preview refresh changes only synthetic account labels and adds missing role accounts without resetting existing passwords or task history. Membership scopes are retained. Group edits continue to affect new assignments, while existing tasks retain their recipient snapshot.

Library folder roots are Orders, Battle Checklists, Formats and Procedures. Formats contains Meetings and General; Procedures contains Operational and Routine. Summaries has Meeting Summaries (Deputies Brief, Deputies Meeting, Safety Committee, Drivers Conference) and Inspections (Armory, Bunker, כ״ס). The user's empty fifth meeting entry is not treated as a folder name. Folder cards show persisted entry counts, including descendants, and support navigation and search across titles, preview text and filenames.

Entries may contain text, files, or both, with title, folder and optional meeting/document date. Each save accepts up to five attachments totalling 3 MiB. Common PDF, Office, text and image extensions are supported. Files are stored durably in PostgreSQL, separately from metadata, and downloaded through an authenticated route with attachment disposition and no-store headers. No public object URLs or browser-local file persistence are used. Metadata responses never expose base64 contents. Library records are explicitly shared within the same organization; viewers can read/download but cannot write, and technical admins do not automatically gain content access. Creators and managers can edit records with optimistic versions; uploads preserve existing attachments. Creation retries use request receipts and content fingerprints.

`0003_document_library.sql` is additive. Local schema setup runs all migrations; the existing exact-project synthetic preview build applies migrations 0002 and 0003 under its advisory lock, then refreshes only synthetic role labels/accounts. Production schema migration remains explicit. No live mail provider was configured by this change.
